# Пример веб-приложения с кэшированием на Flask

Этот проект демонстрирует, как настроить кэширование статических файлов (CSS, JS) в браузере при использовании Flask.

## Структура проекта

```
cache_example/
├── app.py              # Сервер на Flask
├── requirements.txt    # Зависимости Python
├── templates/
│   └── index.html      # HTML шаблон
└── static/
    ├── style.css       # Стили
    └── script.js       # JavaScript
```

## Как это работает

### Настройка кэширования

В файле `app.py` настроены следующие заголовки для статических файлов:

- **Cache-Control**: `public, max-age=31536000, immutable`
  - `public` - файл может быть закэширован любым промежуточным сервером
  - `max-age=31536000` - время жизни кэша 1 год (в секундах)
  - `immutable` - файл не будет изменяться, браузер не должен проверять его актуальность

- **Expires**: дата через 1 год в будущем

Для HTML страницы установлены противоположные настройки - она не кэшируется, чтобы пользователь всегда получал актуальную версию.

### Поведение при обновлении страницы (F5)

1. **Первый визит**: Все файлы загружаются с сервера
2. **Повторный визит/обновление (F5)**: 
   - HTML загружается с сервера (не кэшируется)
   - CSS и JS загружаются из кэша браузера (статус `200 (from cache)` или `304 Not Modified`)

## Установка и запуск

```bash
# Перейдите в директорию проекта
cd cache_example

# Установите зависимости
pip install -r requirements.txt

# Запустите сервер
python app.py
```

Сервер запустится на http://localhost:5000

## Проверка работы кэширования

1. Откройте браузер и перейдите на http://localhost:5000
2. Откройте инструменты разработчика (F12)
3. Перейдите на вкладку Network (Сеть)
4. Обновите страницу (F5)
5. Обратите внимание на столбец "Size" или "Transfer Size":
   - Для `style.css` и `script.js` должно быть указано `(cache)` или `(memory cache)`
   - Для `index.html` файл будет загружен заново с сервера

## Примечание

В режиме разработки Flask (`debug=True`) браузер может игнорировать некоторые заголовки кэширования. Для полной проверки рекомендуется:
- Использовать режим инкогнито/приватного просмотра
- Или собрать приложение для production без debug режима
